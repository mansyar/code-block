## What was built

- **The icons** (`scripts/generate-icons.ts`, `public/icons/`) — six ink blocks on the sun field,
  drawn in code and encoded with node's `zlib` as real 8-bit RGBA PNGs: `icon-192.png` (192×192,
  1014 bytes) and `icon-512.png` (512×512, 4410 bytes). Wired to `bun run icons`, committed, and
  never regenerated by verification (D8).
- **The manifest** (`vite.config.ts`) — `name`/`short_name` "Code Block" (the product's own name,
  display-capitalised), `display: standalone`, `orientation: any`, `theme_color: #f6c445` (the sun
  token, matching the `theme-color` meta in `index.html`) and `background_color: #fdf8ef` (the
  surface token), with both icons declared at their real sizes and `image/png`.
- **The precache** — `globPatterns` cover the shell and built assets
  (`js, css, html, webmanifest, png, svg, ico, json, woff2`), `navigateFallback: '/index.html'` so
  a cold navigation with no cache entry still renders the map, and `cleanupOutdatedCaches`. The
  audio directory is a pattern of its own (`**/*.{mp3,m4a,ogg}`) so the later Chatterbox clips are
  precached by adding files only.
- **The registration** — `injectRegister: 'script-defer'` makes the build emit `/registerSW.js`
  and inject `<script src="/registerSW.js" defer>` into `dist/index.html`, so an installed copy
  registers the worker on load. It is not a file that sits unused.
- **The built-output test** (`src/pwa.test.ts`) — reads `dist/` and asserts the manifest's authored
  fields, that both icons exist in the build and in `public/icons/`, that `index.html` links the
  manifest and loads `registerSW.js` (whose text calls `serviceWorker.register`), that `sw.js`
  lists `index.html`, the hashed JS and CSS, both icons and the manifest, and that a navigation
  fallback is bound to the shell.

## Deviations

- `bun.lock` — the lockfile changed because the phase's declared dependency (`vite-plugin-pwa`)
  was installed. `package.json` is in `Touches`; its lockfile is not named, and installing without
  committing it would leave the project unbuildable for the next person.

No other file outside `Touches` was touched. `index.html` and `src/main.tsx` were deliberately not
edited: the manifest link and the registration script are injected by the plugin at build time, so
registration travels with the built entry page rather than a hand-written call site.
